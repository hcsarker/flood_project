# Flood Prediction and Drainage Simulation

Course project: predicts flood risk using Machine Learning, and simulates
whether a drainage network can handle a rainfall event using the
Rational Method (hydraulics).

## Project Structure
```
flood_project/
├── main.py                     <- run this file
├── data/
│   ├── flood_data.csv          <- PUT YOUR REAL KAGGLE CSV HERE (rename to this)
│   └── flood_data_synthetic.csv<- auto-generated demo data (used if above is missing)
├── src/
│   ├── generate_data.py        <- synthetic dataset generator
│   ├── flood_prediction.py     <- Module 1: ML flood prediction
│   └── drainage_simulation.py  <- Module 2: Rational Method drainage simulation
└── outputs/                    <- all plots, CSVs, and summary_report.txt land here
```

## How to Run
```bash
pip install pandas numpy scikit-learn matplotlib seaborn
python main.py
```

## Using a REAL Kaggle Dataset
1. Go to Kaggle and search "Flood Prediction Dataset" (there are several —
   e.g. datasets by users like `naiyakhalid`, or the "Playground Series
   Flood Prediction" competition dataset).
2. Download the CSV.
3. Rename your target/label column to exactly: `FloodOccurred` (values 0/1).
   - If your dataset uses a probability column (like `FloodProbability`)
     instead of 0/1, convert it first:
     ```python
     df["FloodOccurred"] = (df["FloodProbability"] > 0.5).astype(int)
     df = df.drop(columns=["FloodProbability"])
     ```
4. Save the file as `data/flood_data.csv`.
5. Run `python main.py` again — it will automatically detect and use your
   real data instead of the synthetic one, no code changes needed.

## What Each Module Does

### Module 1 — Flood Prediction (Machine Learning)
- Trains **Logistic Regression** and **Random Forest** classifiers
- Evaluates with Accuracy, Precision, Recall, F1-score, ROC-AUC
- Outputs: correlation heatmap, confusion matrices, ROC curve,
  feature importance chart

### Module 2 — Drainage Simulation (Rational Method)
Formula: `Q = C × I × A / 360`
- Q = runoff (m³/s), C = runoff coefficient, I = rainfall intensity (mm/hr),
  A = catchment area (hectares)
- Simulates a 48-hour rainfall event and compares runoff against a fixed
  drainage capacity to flag **overflow (waterlogging) hours**
- You can tune `C`, `A_hectares`, and `drainage_capacity_m3s` in
  `main.py` -> `run_drainage_simulation(...)` to model a specific area

## Connecting the Dashboard to a Real Model (FastAPI)

`dashboard.html`'s calculator instantly computes the exact formula in-browser
(no server needed). But to get **live Random Forest predictions** (and true
Linear Regression predictions straight from the trained `sklearn` model
object, not just the recovered formula), run the included FastAPI backend:

```bash
cd flood_project
pip install -r api/requirements.txt

# 1. Train + save the models (run once, or whenever flood_data.csv changes)
python api/train_and_save_model.py

# 2. Start the API server
uvicorn api.app:app --reload --port 8000
```

Then just open `dashboard.html` in your browser (double-click the file, or
`python -m http.server` and visit it). It automatically checks
`http://127.0.0.1:8000/health` every few seconds:
- **API running** → top-right badge turns green ("Connected — live FastAPI
  model"), and the two new pills under the calculator show real-time
  predictions from both trained models.
- **API not running** → badge stays gray ("Offline"), and the dashboard
  keeps working using the exact in-browser formula — nothing breaks.

**API endpoints:**
- `GET /health` — check if models are loaded
- `POST /predict` — send all 20 factors as JSON, get back both models'
  predicted `FloodProbability` + risk level. Interactive docs at
  `http://127.0.0.1:8000/docs` (Swagger UI, auto-generated by FastAPI).

```bash
curl -X POST http://127.0.0.1:8000/predict -H "Content-Type: application/json" -d '{
  "MonsoonIntensity":5,"TopographyDrainage":5,"RiverManagement":5,"Deforestation":5,
  "Urbanization":5,"ClimateChange":5,"DamsQuality":5,"Siltation":5,"AgriculturalPractices":5,
  "Encroachments":5,"IneffectiveDisasterPreparedness":5,"DrainageSystems":5,"CoastalVulnerability":5,
  "Landslides":5,"Watersheds":5,"DeterioratingInfrastructure":5,"PopulationScore":5,"WetlandLoss":5,
  "InadequatePlanning":5,"PoliticalFactors":5
}'
```

> Note: `allow_origins=["*"]` in `api/app.py` is fine for local development/demo,
> but should be restricted to your actual frontend URL before any public deployment.
